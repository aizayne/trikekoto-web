Read the status column first. Most of this roadmap is built, deployed, and covered by 400 passing tests — 201 Dart and 199 against the Firestore emulator.

The backend is finished. Blaze cleared the one dependency that had grown to block four things at once, and everything behind it has since shipped: four gen-2 Cloud Functions live on Node 22, the scheduled dispatch sweep firing every minute, rating aggregates moved server-side and the client's write refused at the rules layer, Cloud Storage provisioned, a ₱500 budget alert, and the SMS region policy narrowed to the Philippines.

The commuter half is real. A live phone number received a live OTP on the public web build, and pickup now defaults to the commuter's own position, reverse-geocoded into an address. Dispatch ranks by road distance rather than crow-flies.

The system is now documented as built. Step 10 closed with 38 screen plates drawn from the real theme, and a re-trace of the screen flows that had to correct rather than extend them — the old version described anonymous entry that mandatory accounts had already removed. Drawing an app from its own source turns out to be an unusually good way to find where the code and the story about it have drifted apart: it surfaced two live defects, both since fixed and shipped.

What is left is not infrastructure. It is a complete ride on real handsets (75, 78), App Check on web — the last unmitigated part of the SMS fraud surface — and self-hosting OSRM, which the road-distance change made matter sooner than it did.

The two numbers have converged. They sat nine points apart all week — a build far ahead of its evidence. A complete field test on real hardware closed the gap, and it closed from the evidence side, which is the only direction that counts.

96% counts steps, and steps are not the same size. The four that remain are almost all validation — and for a capstone, testing is a chapter rather than a coda.

Weighted so that proving the system counts for as much as building it, the honest figure is about 95% — the mean of the six areas below, and not worth pretending is more precise than that. The build is nearly finished; the evidence is barely started. Quote 95% and a panel will ask what has actually been demonstrated.

Worth noticing what did not move it. The security review went from one open High finding to zero findings — App Check enforced on both platforms, keys restricted, region policy, budget alert — and the headline barely shifted. That is the point: the gap is not security, and it is not code. It is that nobody outside this project has used the thing.

One change did lower the cost of closing it. The APK now installs from an HTTPS link instead of a LAN server, so a tester no longer has to be on the same Wi-Fi — or in the same building. That does not move the percentage, because handing someone a build is not the same as watching them use it. It removes the logistics excuse.

The number moved because rides happened. Validation went from 15% to 75% in one afternoon, and the only code written was two fixes the testing itself uncovered. Phases 00–06 ran on real hardware: permissions, a real GPS fix, a 50 m walk, a presence document deleted rather than flagged, a live OTP, a self-filling pickup with an accurate address, a greedy offer, a push waking a backgrounded phone, and a rating that incremented exactly once. Then failure paths, the kill switch, and the screens built that morning.

Two real defects surfaced, both found by preparing to test rather than by testing: a ride booked when nobody was online would have waited forever, because the candidate budget it was supposed to exhaust is never spent when there are no candidates; and the admin ID queue had no composite index and would have failed on first open. Neither was reachable by the 400 automated tests.

The remaining 30% is not more of the same. It is somebody who is not the author: real TODA drivers, on their own handsets, in Filipino, without the person who built it standing next to them. That is step 78, and nothing about it is technical.

And one number moved down, then back. ID verification shipped complete and well tested, and backend & security fell from 100% to 95% — it had introduced sensitive personal information whose 90-day retention nothing enforced. Deploying purgeExpiredIds restored it. Recorded because a score that only ever rises is measuring effort rather than state.

Then the ride itself, across two handsets: pickup filled itself in and the reverse-geocoded address was accurate enough for a driver to act on; the greedy sweep offered to the nearest driver within a timeout; a push woke a backgrounded phone — the single largest documented limitation of this project, retired; accept, start and complete propagated to both screens; the commuter’s cancel button disappeared on in_transit; and a rating incremented the driver aggregate exactly once, proving this morning’s client-to-function cutover was ordered correctly. What remains is not the author testing: it is somebody else. UAT with real TODA drivers on their own handsets (78) has not started, and that is the whole of the missing 30%.
What would move the number most. Step 75 phase 03 — real permission prompts, real GPS, a fifty-metre walk — needs two numbers that can receive SMS and about fifteen minutes. It is the cheapest large gain on this roadmap, and nothing else has to be built before it can happen.
