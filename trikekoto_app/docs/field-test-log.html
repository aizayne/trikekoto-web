Rewritten 9 September 2026. The first version of this sheet was written before commuter accounts, before the Cloud Functions were deployed, and before fares were removed. Six of its steps expected the opposite of what the system now does — three of them described deployed features as known limitations, so a tester following it would have recorded real successes as expected failures.

If you have a part-finished run against the old sheet, its Phase 04, 05, 07 and 08 results are not comparable to this one. Reset and start clean.

Known limitations — record these, they are not failures

  • Any signed-in user can list online drivers. The greedy match runs on the commuter's device, so it must query active_drivers. That document deliberately carries no name, phone, plate or rating — an email and a coordinate is the whole exposure. Closing it means moving dispatch fully server-side and switching canDiscoverDrivers() to isAdmin(); the client sweep has to stop first, or no ride is ever offered (step 69).
  • App Check is unenforced on the web build. Play Integrity attests the APK, but providerWeb is null pending a reCAPTCHA Enterprise key, so nothing distinguishes a browser from a script. The SMS region allowlist (Philippines only) is what bounds the damage meanwhile.
  • Routing runs against the public OSRM demo server. Rate-limited and licensed for development only. Under throttling, dispatch silently falls back to straight-line ranking and the route line to a padded estimate — degraded, never broken. Self-host before a real pilot.
  • Search is bounded to about 55 km around the map centre. Correct for a service where no trip is that long, but it means a distant place returns nothing. The message says so rather than claiming the place does not exist.

If a step fails, stop and note the state. Screenshot the screen, and open the Firestore console to record what the document actually holds. A failure you can only describe from memory is one you will not be able to reproduce tomorrow.
